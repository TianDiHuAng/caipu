# PRD — 中外菜谱网站（Recipe Atlas）

> 版本：v1.0 ｜ 状态：已定稿，进入开发
> 本文档为需求唯一来源，功能变更必须同步更新本文档与 `docs/DECISIONS.md`。

---

## 1. 产品定位

一个覆盖「中国各地菜系 + 世界主要料理」的**结构化菜谱库**，面向三类使用者：

| 使用者 | 核心诉求 | 对应能力 |
| --- | --- | --- |
| 家庭做饭的人 | 找到能照着做的菜，知道量和火候 | 详情页、份量换算、单位切换、打印视图 |
| 想学某菜系的人 | 系统性地浏览一个菜系的面貌 | 菜系页、分类页、分类树、关联推荐 |
| 手上有什么就做什么的人 | 用现有食材反查能做的菜 | 食材反查页 |

产品形态：**数据层 + REST API + Web 站点**，三者解耦。App 与小程序后期复用同一套 API，不重复建设。

---

## 2. 用户与场景

### 2.1 用户画像

- **U1 做饭新手**：需要明确的量、火候、判断熟度的线索。对"适量""少许"零容忍。
- **U2 有经验的家常厨师**：需要正宗做法、变体、替代方案、常见失败原因。
- **U3 菜系探索者 / 内容读者**：关心来历、文化背景、地域差异，会按菜系/品类浏览。
- **U4 有饮食限制的人**：需要按过敏原、素食、无麸质、清真等标签精确筛选。

### 2.2 关键场景

1. 搜"宫保鸡丁"，进入详情页，把份量从 2 人改成 4 人，用量自动翻倍，进厨房打印。
2. 打开「川菜」菜系页，看到该菜系的品类分布，点「凉菜」看全部川式凉菜。
3. 冰箱里有五花肉和青蒜，在食材反查页输入两者，得到「回锅肉」。
4. 输入"无麸质 + 素食 + 30 分钟内"，得到符合条件的菜列表。
5. 在手机浏览器打开同一网址，布局自适应，不横向滚动。

## 3. 功能清单

### 3.1 已实现范围（P0）

| 编号 | 功能 | 说明 |
| --- | --- | --- |
| F-01 | 菜谱列表 | 分页、排序（更新时间/难度/总时长）、筛选 |
| F-02 | 菜谱详情 | 全部字段渲染，含安全提示、过敏原、估算营养 |
| F-03 | 全文搜索 | 菜名（中/英/原文名）、食材名、标签、简介 |
| F-04 | 多维筛选 | 菜系、品类、食材、难度、口味、饮食标签、总时长、过敏原排除 |
| F-05 | 分类树 | 区域 → 菜系 → 品类 → 数量 |
| F-06 | 菜系页 | 单菜系概览 + 该菜系全部菜谱 + 品类入口 |
| F-07 | 分类页 | 单品类跨菜系聚合 |
| F-08 | 食材反查 | 输入多个食材，按命中数排序，支持"只显示全部命中" |
| F-09 | 随机推荐 | 无状态随机，支持按菜系/品类收窄 |
| F-10 | 份量换算 | 客户端按 servings 比例缩放用量，保留可读精度 |
| F-11 | 单位切换 | 公制（g/ml）↔ 常用厨房计量（茶匙/汤匙/杯/盎司） |
| F-12 | 打印视图 | 无导航/无广告的纯菜谱版式，A4 友好 |
| F-13 | 收藏 | 本地存储（localStorage），不依赖登录 |
| F-14 | SEO | schema.org/Recipe 结构化数据、sitemap.xml、robots.txt、Open Graph、canonical |
| F-15 | 多语言 | 数据字段 zh/en 双语；界面 i18n 预留，默认中文 |

### 3.2 明确不做（P1 及以后）

- 用户账号与云端收藏（当前用 localStorage）
- 用户上传菜谱、评论、评分
- 图片托管（本阶段不采集图片，字段留空 + 占位图）
- 智能配餐、购物清单导出（P1）

## 4. 页面清单与验收标准

| 页面 | 路由 | 验收标准 |
| --- | --- | --- |
| 首页 | `/` | 展示菜系统计、热门菜谱、品类入口；LCP 元素为文本，无阻塞字体 |
| 分类总览 | `/categories` | 展示分类树，每个品类显示菜谱数；链接可点至分类页 |
| 分类页 | `/categories/[slug]` | 列出该品类菜谱，分页 ≥20/页，含面包屑 |
| 菜系总览 | `/cuisines` | 展示全部菜系，按区域分组 |
| 菜系页 | `/cuisines/[slug]` | 菜系简介 + 品类分布 + 该菜系菜谱；面包屑正确 |
| 菜谱详情 | `/recipes/[id]` | 全部字段渲染；含 Recipe 结构化数据；份量换算与单位切换可用；打印按钮可用 |
| 打印视图 | `/recipes/[id]/print` | 隐藏导航，保留配料表与步骤，`@media print` 生效 |
| 搜索页 | `/search?q=` | 关键词命中菜名或食材；空结果有提示；支持筛选参数 |
| 食材反查 | `/ingredients?q=` | 多食材命中排序；「仅全部命中」开关生效 |
| 移动端 | 全站 | ≤390px 宽无横向滚动；点击目标 ≥44px |
| API 文档页 | `/api-docs`（开发期） | 列出全部端点与示例响应 |

## 5. 非功能需求

- **性能**：列表接口 P95 < 150ms（本地 SQLite）；首页首屏 JS < 200KB（gzip）。
- **SEO**：所有菜谱详情页服务端渲染，HTML 内含完整正文与 JSON-LD。
- **一致性**：网站、App、小程序统一走 `/api/v1`，字段不得单端私有化。
- **可迁移性**：ORM 层抽象，SQLite → PostgreSQL 只需改连接串与迁移。
- **内容质量**：全部菜谱必须通过 `scripts/validate`，详见 `docs/STYLE.md`。

## 6. 数据规模目标

- 菜谱总数 ≥ **3000**，按「菜系 × 品类」格子推进，目标矩阵见 `docs/TAXONOMY.md` 与 `tasks/progress.json`。
- 覆盖中国 21 个菜系/地方风味 + 外国 33 个料理体系。
